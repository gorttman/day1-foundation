# Grafana

**Status:** LIVE (ArgoCD app `grafana`, auto-sync). Namespace `monitoring`,
shared with influxdb. Image `grafana/grafana:13.0.3`.

## Access
- LAN: https://grafana.i3sec.com.au (Traefik ingress, Let's Encrypt cert via
  `letsencrypt-prod`; Pi-hole resolves it to the Traefik VIP).
- Off-LAN: listed in `tunneled_hostnames` in `apps/cloudflare-tf`, so it is
  reachable through the Cloudflare tunnel behind the zone-wide mTLS WAF rule.
- Login: local `admin` account. First login is `admin` / `admin` and Grafana
  forces a password change. No SSO, no anonymous access. The password lives in
  Grafana's database, not in git (see Storage).

## Data source
The InfluxDB data source is provisioned from a ConfigMap (`grafana-datasource-cm.yml`):
Flux, uid `influxdb-pilab`, pointing at `influxdb.monitoring.svc:8086`. Org, default
bucket and token come from the `grafana-influxdb` SealedSecret. The token is an
InfluxDB all-access token; scope it down if desired. Dashboards name their bucket
explicitly, so the default bucket does not matter.

## Dashboards (provisioned from git)
Three providers, three folders. Grafana rescans every 60 s, so no restart is needed.
UI edits are not written back to git: change the JSON and commit.

- **Reports** folder: ConfigMap `grafana-dashboards` (`grafana-dashboards-cm.yml`).
  Currently the Subscriptions dashboard, reading bucket `subscriptions`.
- **Reports** folder, second provider/ConfigMap: `grafana-dashboards-icloud-migration`,
  generated from `dashboards/icloud-migration.json` - same folder as Subscriptions,
  kept as its own ConfigMap/provider/mount rather than merged into the ConfigMap
  above so it could use the newer plain-JSON-file pattern (see Platform below)
  without touching the older embedded-YAML one. Bucket `icloud_migration`, written
  by `day2-services` apps/icloud-migration-status`'s CronJob. Links to
  `reports.i3sec.com.au/icloud-migration/` and back.
- **Platform** folder: ConfigMap `grafana-dashboards-platform`, generated by
  `kustomization.yml` from the JSON files in `dashboards/`. Each links to the other.
  - `cluster-overview.json`: nodes (CPU, memory, swap, load, temperature, disk,
    network), top pods, ArgoCD apps needing attention, Longhorn health, certificate
    expiry, InfluxDB health. Bucket `telegraf`.
  - `ai-platform.json`: LiteLLM router, route validation, session memory, AI pod
    memory. Bucket `ai_metrics`. Panels fill in as build-plan Stages 1 to 3 land;
    the write schema they expect is in `apps/telegraf/README.md`.

Layout is two panels per row at most, so it stacks cleanly on a phone. Keep it that
way when adding panels. Every Flux query was tested against synthetic data before
commit; do the same for new ones.

## Alerting

Provisioned from git since 2026-09-26 (`grafana-alerting-cm.yml`, mounted at
`/etc/grafana/provisioning/alerting`) - previously not provisioned at all. One rule
so far: `icloud-migration-alerts` watches for a migration category stuck
`in_progress` with zero movement for 2+ hours, prompted directly by the Paperless
consume queue sitting stuck a full week unnoticed. **No contact point/notification
policy is provisioned yet** - rules fire and show red in the UI/API, but nothing is
wired to actually deliver a notification externally.

## Storage: RAM data dir plus Longhorn backups
The data dir (SQLite) is a RAM `emptyDir`. Two sidecars persist it to the Longhorn
PVC `grafana-data-backup`:
- a daily tar during 15:00 to 19:00 UTC (about 01:00 to 05:00 Sydney), one
  previous generation kept, and a final tar in the `preStop` hook on graceful stop;
- an init container restores the newest good tar on pod start.

After an unclean node death, up to about 24 hours of UI changes are lost, including a
changed admin password (it would revert to `admin` with a forced change). The
provisioned data source and dashboards are ConfigMaps and are never at risk.
